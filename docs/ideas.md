## 英語のページを読みながら知らない単語をメモするアプリ

- なぜ欲しいのか：英語のページを読んでいて知らない単語が出てくるたびに調べているが以下の問題がある
  - 一度では覚えられない
  - 調べて暗記しただけで終わるので、データの蓄積がなく、再び単語がわからなかった場合に調べ直しになる
    - 調べ直すにしても、再度辞書を調べるとかより自作の単語帳などにしたい
  - 複数の単語がわからないが、なんとなく文は読めるという状態で、読み進めることを優先したい場合に読めなかった単語をメモしておいて後で調べたい
  - タブを別途開いて調べたりメモしたりするのが面倒なので、少なくともメモなどは同じタブで作業したい
    - 記事ページをインラインブラウザなどで開いて、単語をダブルクリックすると右サイド（位置は仮）の単語帳が開いて、登録済みだったら編集、未登録だったら新規登録状態になる。
- 一言で：英文を読みながら単語帳を育てるアプリ
- 状態：作る

## v0.2 の候補（2026-10-18）

v0.1 の対象外なので、v0.1 を出してから検討する。

- 自由なメモの欄。今は意味の欄に見出しなしで書けばメモとして残る。専用の欄にするなら、保存の形に `note` を足す
- 日本語訳の欄（空でもよい）。自動入力は ADR-0001 で対象外にしたので、手で入力する欄だけ。今は意味の欄に書き足せる。専用の欄にするなら、保存の形に `translation`（`null` 可）を足す
	- `note` と `translation` を足すときは、書き出しのファイルの版を上げるか、版 1 のファイルも読めるようにする
- 発音を確かめる
	- 済（2026-10-22）: 見出し語と文脈の文の横に読み上げボタン。ブラウザ内蔵の `speechSynthesis` で、通信も API キーも要らない
	- 済（2026-10-22）: 文脈の文も読み上げる（2026-10-22 の試用のフィードバック）。これまでの文脈と一覧の文脈にも付けた。参考: https://zenn.dev/kogawakaito/articles/listening_tool
	- Oxford Learner's Dictionaries の、その語のページへのリンク（`https://www.oxfordlearnersdictionaries.com/definition/english/<語>`）。音声と発音記号はそちらで確かめる
- 関連する単語の結び付け（`goalkeeper` から `goal` へのリンクなど）。活用形の自動変換（v0.1 の対象外）と合わせて考える
- 一覧から単語の編集画面に移る。今の編集画面は「今読んでいる文」を文脈に足す前提なので、一覧から開いたときは文脈を足さずに保存する形を足す。ADR-0001 では一覧を表示と削除だけにしている
- パネルの見た目（2026-10-18 に普段の Chrome で触っての感想）。白い背景に同じ書体の文字だけで、見出し語、意味、文脈の区切りがわかりにくい
	- セクションをカードや区切り線で分ける、見出し語を大きく別の書体にする、品詞をラベルにする、ダークモードに対応する
	- CSS だけで済み、データと動きは変わらない。v0.1 の対象外の機能ではないので、1 週間使う前に入れてもよい
	- 2026-10-18 に、3 案から「アクセント」（緑の見出しラベル、文脈は左線の引用、一覧はカード、ダークモード対応）を選んで入れた
- 英辞郎（購入済みのテキストデータ、Ver.144.10）の訳を、読み取り専用でパネルに出す
	- ADR-0001 で日本語訳の自動入力を見送った理由（翻訳 API のキーと無料枠）が当てはまらない。入れるなら ADR-0002 で判断を残す
	- テキストを Node のスクリプトで見出し語の先頭の文字ごとの JSON に変換し、`extension/` の下の git 管理外のフォルダに置く。パネルは該当するファイルだけを読む。ファイルがなければ欄を出さない
	- 再配布できないデータなので、元のファイルも変換後のファイルもコミットしない。`.gitignore` に加えて、コミットされていないことを CI で確かめる。書き出しと読み込みのデータにも含めない
	- 利用条件は 2026-10-18 に購入ページで確かめた。使えるのは購入者本人だけで、第三者が使える状態にするのは禁止（【5】）。形式の変換は禁止ではなく、無保証という扱い。自分の拡張から引くのは本人の利用に当たるが、public のリポジトリに 1 度でも push すると禁止事項に当たる
	- 元のファイルは `EIJIRO144-10.TXT`（Shift JIS、CR+LF、153MB、約 258 万行、約 199 万項目）。Node の `TextDecoder("shift_jis")` で読める
