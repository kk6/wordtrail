# ADR-0001: 英文を読みながら単語帳を育てる自分専用ツールを作る

## Status

proposed

## Date

2026-10-18

## Context (Why)

週に数回、英語の技術ドキュメントや記事を読んでいる。知らない単語が出てくるたびに調べているが、次の問題がある。

- 一度調べただけでは覚えられない。
- 調べた結果がどこにも残らないので、同じ単語がまたわからなくなると、辞書を引き直すことになる。実際に、前に調べた単語をもう一度調べることが起きている。
- 文の意味はなんとなく取れていて、読み進めるのを優先したいときがある。そのときは知らない単語をメモだけしておき、あとで調べたい。
- 調べたりメモしたりするために別のタブを開くのが面倒。

既存サービスとして Readlang を実際に試し、LingQ も検討した。クリックするだけでその場で単語帳に保存できる使い心地は良かった。一方で、次の点が合わなかった。

- 有料のプランがある。
- 多言語に対応しているが、英語しか必要ない。
- 用途のわからない機能や、チュートリアル的な登録の手順があり、自分には要らない。

英語専用で、自分が使う機能だけを持ち、動作の軽いツールが欲しい。

## Intent (What)

普段使っているブラウザで英語のページを読みながら、読んでいるタブを離れずに単語を登録し、自分の単語帳として貯めていけること。

受け入れ条件:

1. 同じタブの横に単語帳の画面を開いておき、読んでいるページで単語をダブルクリックすると、その単語が単語帳の画面に出る。画面が閉じているときのダブルクリックでは画面を開かず、次に開いたときに最後の単語が出る（コピーのためのダブルクリックで、読書が遮られないようにするため）。
2. 未登録の単語なら新規登録の画面、登録済みの単語なら、保存してある内容を表示・編集する画面になる。
3. 新規登録の画面には、次の内容があらかじめ入っている。
   - 見出し語（クリックした語を小文字にしたもの）
   - その語を含む文（文脈）と、ページの URL
   - 英英辞書から取得した意味（品詞ごとに複数あってもよい）
4. 見出し語と意味は、保存する前に手で直せる。辞書に見つからなかった場合は、意味の欄は空になり、手で入力できる。
5. 同じ単語かどうかは見出し語の一致で判定し、大文字・小文字は区別しない。
6. 登録済みの単語を別の文でダブルクリックすると、その文と URL が文脈の一覧に追加される。すでにある文と同じなら追加しない。
7. 登録した単語を、新しく登録した順に一覧で見られる。一覧から単語を削除できる。
8. 単語帳の全データを 1 つのファイルに書き出し、そのファイルから読み込める。
9. ツールを読み込み直したり、ブラウザを再起動したりしても、単語帳の内容は消えない。

## v0.1 の完成条件

次の 5 つをすべて確かめられたら、v0.1 は完成とする。

1. 種類の違う英語のページ 3 つ（MDN、英語のニュース記事、GitHub の README）で単語をダブルクリックすると、新規登録の画面が出る。見出し語、意味、文、URL が入っている。
2. 保存した単語を別のページでダブルクリックすると、編集画面が出て、文脈が 2 件になる。同じ文でもう一度ダブルクリックしても、3 件にはならない。
3. 拡張の再読み込みと Chrome の再起動の後も、登録した単語がすべて一覧に残っている。
4. 書き出したファイルを、拡張を削除して入れ直した後に読み込むと、全単語と全文脈が元に戻る。読み込みは確認のダイアログを出した後、今ある単語帳を丸ごと置き換える。
5. 実際の読書に 1 週間使い、10 語以上を登録できている。

5 は機能のチェックではない。作ったのに使わなかった、で終わっていないかを確かめるための条件である。

## v0.1 の対象外

次のものは v0.1 では作らない。理由と、足すときの条件は Alternatives Considered に書いた。

- 登録済みの単語のハイライト
- フラッシュカードや間隔反復による復習
- 活用形の自動変換
- 熟語の登録
- 日本語訳の自動入力
- 他の PC との同期

次のものも v0.1 では扱わない。

- 拡張が動かないページ。Chrome の PDF ビューア、`chrome://` のページ、Chrome Web Store、Google ドキュメントのように画面を独自に描画するサイトでは、ダブルクリックで登録できなくてもよい。
- 一覧の検索、並べ替え、タグ付け。一覧は新しく登録した順の表示と削除だけにする。数百語に増えて探しにくくなったら検討する。
- 辞書が使えないときの再試行やキャッシュ。取得に失敗したら意味の欄を空にするだけにする。
- 文の切り出しの精度。`e.g.` や `U.S.` のような略語のところで文が途中で切れても直さない。保存前に文脈を手で直す機能も作らない。
- 読み込み時に今ある単語帳と合わせる機能。読み込みは置き換えだけにする。

## Constraints

- 自分が使うためだけに作る。ストアでの公開、アカウント登録、チュートリアルは持たない。
- サーバーを持たない。外部サービスに依存するのは、意味を取得する辞書だけにする。その辞書も、API キーや課金なしで使えるものに限る。
- 対象は英語だけ。翻訳や他の言語には対応しない。
- 使うブラウザは Chrome の 1 種類、PC は 1 台を想定し、他の PC との同期はしない。
- 読むのを邪魔しない軽さを保つ。ページを読み込んだ時点で、ページ全体を処理するようなことはしない。

## Alternatives Considered

- **既存サービス（Readlang、LingQ）をそのまま使う**: 使い心地は良いが、有料のプラン、多言語対応、不要な機能やチュートリアルがあり、「英語専用・必要最低限・軽い」という要望に合わない。
- **自作アプリの中に記事を埋め込んで表示する**: アイデアの最初の形はこれだった。しかし多くのサイトは埋め込みを禁止しており、表示できないページが頻繁に出る。避けるには本文を取り出して描き直す仕組みが必要になり、作るものが大きくなりすぎる。
- **記事の本文を貼り付けて読むアプリ**: 作るのは一番簡単だが、貼り付けの手間が「別タブが面倒」という不満と矛盾する。
- **意味を自動で入力しない（あとで手で調べる）**: 依存を一番減らせるが、登録した時点で意味が見えないと困るので採用しなかった。
- **翻訳 API で日本語訳を自動入力する**: API キーの管理と無料枠の上限が負担になる。
- **登録済みの単語をページ上でハイライトする**: 「覚えられない」問題には効くが、v1 では見送る。同じ単語を何度もダブルクリックしていると文脈の数で分かったら追加を検討する。
- **フラッシュカードや間隔反復による復習**: 作る量が一番多い。必要になったら、書き出したデータを Anki などの既存ツールに移せば済む可能性が高い。
- **活用形を自動で原形にする**: 依存が増え、変換を間違えることもある。v1 では見出し語を手で直すことで対応し、判定が外れて困ることが続いたら再検討する。
- **他の PC との自動同期**: 使える容量が小さいか、認証などの仕組みが必要になる。PC が 1 台なので不要。
- **熟語（複数の単語）の登録**: v1 ではダブルクリックで選べる 1 語だけにする。

## Consequences

ポジティブ:

- 調べた単語と、それが出てきた文が貯まっていくので、辞書を引き直す必要がなくなる。
- 読んでいるタブを離れずに登録できるので、読み進めるのを優先できる。
- 文脈の数が「何回わからなかったか」の記録になり、ハイライトなどの機能を足すかどうかを判断する根拠になる。
- 機能が少なく、外部への依存も辞書だけなので、軽く、保守しやすい。

ネガティブ:

- 単語帳のデータはこの PC のブラウザの中にしかない。バックアップは手動の書き出しに頼る。
- 活用形は同じ単語と判定されないので、`ran` と `run` のように別々に登録されることがある。
- 意味は英英なので、日本語訳が欲しいときは自分で書き足す必要がある。
- 辞書サービスが止まったり仕様が変わったりすると、意味の自動入力が使えなくなる（手での入力はできる）。
- 復習の機能がないので、「覚えられない」問題の解決は、繰り返し出会うことと、編集画面で文脈を見返すことに頼る。
